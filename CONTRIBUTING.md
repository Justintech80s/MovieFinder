# Contributing to MovieFinder

Thanks for your interest in improving MovieFinder.

## Good contribution areas

Contributions are especially useful when they improve cinema search, graph intelligence, streaming availability, verification, ingestion, and search quality.

High-value contributions usually include one or more of the following:

- a reproducible bug fix
- an automated test that protects important behavior
- a measurable performance or reliability improvement
- clearer documentation for setup, architecture, or deployment
- a well-scoped feature with explicit acceptance criteria
- a security or privacy improvement that preserves existing behavior

## Before you start

1. Read the README and relevant documentation.
2. Search existing issues and pull requests to avoid duplicating work.
3. For large or architectural changes, open an issue first and describe the proposed approach.
4. Never commit real API keys, access tokens, private user data, or production secrets.

## Development workflow

1. Create a focused branch.
2. Keep the change as small and testable as practical.
3. Add or update tests when behavior changes.
4. Run the project's test suite locally.
5. Open a pull request using the repository template.
6. Explain what changed, why it matters, how it was verified, and any remaining limitations.

## Pull-request quality bar

A strong pull request should be:

- focused on one problem
- easy to reproduce and review
- backed by tests or concrete evidence
- compatible with the project's security and privacy boundaries
- honest about incomplete work or external dependencies

## AI-assisted contributions

AI tools may be used to help write or review code, but contributors remain responsible for correctness, licensing, security, and testing. Do not submit generated code that you cannot explain or verify.

## Recognition

Meaningful contributors are welcome. The goal is to build a project history where merged pull requests clearly show useful, reviewable engineering work.
